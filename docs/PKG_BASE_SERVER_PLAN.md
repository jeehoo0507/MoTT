# 보고서용 MoTT 패키지형 개선: 서버 역할과 판정

## 서버 1 — 진단과 개선안 선정

Codex는 ~/R2E-codex 전용 worktree/branch에서 실행한다. ~/R2E에서 진행 중인 실험은 유지한다.
목표는 기본 MoTT를 패키지형에서도 개선하는 것이며, 루프/Delta의 성공을 강제하지 않는다.

1. 실패를 작업 격자 실패, 격자와 정확 검사 불일치, stop/행동 소진/max_steps로 분해한다.
2. 학습·validation에서 원인을 재현한다. 이미 본 pkg16 평가는 탐색 기록으로 남긴다.
3. 증거가 있는 변경 하나와 동예산 baseline만 pilot 비교한다. 원본 GPU 큐가 비어야 시작한다.
4. 새 실험 전에 가설·데이터·seed·예산·선정 기준을 고정한다. 단순 검사/탐색 추가 효과를 모델 개선으로 부르지 않는다.
5. 개선안이 선정되면 코드/설정 hash와 서버2용 실행기를 준비한다. 선정이 안 되면 baseline을 유지한다.

## 서버 2 — 지금 할 일

Delta 6 arms x 3 seeds는 이미 완료됐다. 같은 표를 얻기 위한 재학습은 하지 않는다.
`scripts/pkg_delta_report.py`로 다음을 정리하고 작은 결과 archive를 만든다.
- 종류·크기·seed별 성공률, 정책 시간/배치 시간/검사 시간, 모델 파라미터 수와 학습 시간
- Delta vs GRU, Delta+aux vs Delta, Delta+aux vs GRU+aux, 최종 후보 vs MoTT의 paired rescued/harmed
- 공동 성공 문제에서 부품 수 차이와 정확 검사 초과량, 같은 문제의 seed 반복을 독립 표본으로 세지 않음
- 처음 6문제의 짧은 별도 파일럿임을 명시하고 본평가 숫자와 합치지 않음

## 서버 2 — 후보 선정 후에만 할 일

서버1의 선정 후보 하나와 동일 예산 재학습 baseline을 3개 새 학습 seed로 독립 비교한다.
PCB/PKG/IP, 10/16 크기를 모두 평가한다. 새 holdout 2파일 x 25문제/조건을 사용한다.
확인 학습 seed는 610/611/612로 고정한다. 새 test pool seed는
8600000 + tech_id*100000 + side*100 + file_id (pcb/pkg/ip의 tech_id=0/1/2, side=10/16,
file_id=0/1)로 고정한다. 이 pool을 후보 선정이나 checkpoint 선택에 사용하지 않는다.
학습 예산은 arm당 증류 .75h + RL 1.25h, 교사·원본 학습법·데이터가 baseline과 후보에서 동일해야 한다.
두 모델×3시드의 GPU 예산은 합계 12h이며, 풀 생성/평가 시간은 별도다.
후보 동결 후, 평가 실행 전 나머지 평가 규칙/부품 수 비교/시간 측정 환경을 문서에 고정한다.
원본과 동일 학습 예산·교사 구성·검사 루프를 유지하며, 추가 검사나 탐색 비용도 시간에 포함한다.
주 지표는 pkg16 정확 성공률의 paired 변화, 보조 지표는 pkg10, PCB/IP 손해 여부,
공동 성공의 부품 수, 전체 시간이다. 모든 조건을 보고하며 좋은 조건만 선택하지 않는다.
탐색 결과를 본 뒤 확인 실험의 성공 임계값/비열등 한계를 바꾸지 않는다.

## 보고서 배치

- 본문: 기본 MoTT의 동작 원리와 기존 공정 비교, 최종 선정 개선안이 있다면 그 비교.
- 추가 실험: 패키지형 실패 진단. 마스크만 열어서는 개선이 없었다는 결과도 남긴다.
- 확장/ablation: Delta/GRU/loop. pkg10 일부 개선은 관찰됐지만 크기 간 일관성은 없었다고 기술.
- 한계: 합성 환경, 원본 baseline 재현 수준, 개선안의 독립 검증 범위. 탐색을 확증으로 포장하지 않는다.
