NEW SERVER ONLY: clone and run. No files, credentials or SSH connection from server 1.

git clone https://github.com/jeehoo0507/R2E.git R2E-loop
cd R2E-loop
bash scripts/server2_fresh.sh

Requires Linux, Python >=3.10 with venv, git, flock, NVIDIA driver, internet for dependencies,
and RAM sufficient for the existing PDN generator. Dataset generation is CPU/memory intensive.
The launcher installs dependencies, checks CUDA, and detaches with nohup. It can run without an agent.
Do not run the old server2_loop.sh or server2_once.sh alongside it.

AUTOMATIC STEPS
1. Generate 27 training pools and 3 validation pools locally with the repository's fixed seeds,
   sizes and certified greedy+prune pool builder. Reuse the teacher solutions tracked in Git;
   no teacher/checkpoint/pool file is fetched from server 1.
2. Train r2pk (MoTT+P1) and r3pk (loop+P1) for seeds 0, 1, 2. Interleave the pair for each seed.
   Each run has the existing 0.75h distillation + 1.25h RL budget. Six runs = 12 GPU-hours nominal.
3. Concurrently generate evaluation pools: 10/16 have 25 instances per file; 20 has 8.
   Each board kind pcb/pkg/ip has two files per size, matching the planned sample counts.
4. Evaluate both models on 10/16/20. Then evaluate r3pk at R2/R4 on 16/20, reusing R8 outputs.
5. Save per-file summaries and a compressed results archive. Attempt a GitHub upload if credentials
   are already configured; upload failure does not remove results or prevent experiments.

This is a separate matched comparison, not a replay of server 1's saved checkpoints. Dataset seeds
are reused, but byte-identical regenerated inputs across software environments are not assumed.
Do not combine the new measurements with the old L1/L2 verdicts or call them independent new seeds.
The transfer-based L1 checkpoint evaluation and exploratory lo_pcb run are not part of this new mode.

PROGRESS
python3 scripts/server2_once.py status --fresh
tail -f agent/logs/s2_fresh/launcher.log

Initially status.stage is building_train_val. Training begins once those pools are ready.
Generation details: agent/logs/s2_fresh/build_*.log
Training details: agent/logs/s2_fresh/train_*.log
Success: final=true, done=180, failed=0, blocked=0.
Phases: F10=36 evaluation files; Fbig=72; FR=72.

OUTPUT
server2_fresh_results.tgz
agent/logs/s2_fresh/summary.csv
runs/2026-11-05fresh/
runs/pool_s2_fresh/ (generated inputs, never uploaded to GitHub)

Resume with the same bash command in the same directory; completed stages/results are reused.
No new data seeds or hyperparameters are chosen based on observed results.

OPTIONAL UPLOAD AFTER AUTHENTICATION
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
python3 scripts/server2_once.py publish --fresh

GitHub CLI is only needed for this optional device-login flow, not for running the experiment.
No global Git author identity needs to be configured. Results are committed from an isolated checkout.

TIMING
On 1 GPU: nominal training-only budget is 12h; on 2 GPUs: 6h; on 3 GPUs: 4h.
Data generation, loading, validation and 180 evaluation files add time. Some overlap with training.
The certified 16/20 pool generation can be particularly slow. Next-day completion of all phases
is not guaranteed; the 10x10 comparison has priority and the archive is refreshed on phase completion.
