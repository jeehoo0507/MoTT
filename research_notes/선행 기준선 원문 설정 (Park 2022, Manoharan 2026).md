## 1. Park et al., "Transformer Network-based RL Method for PDN Optimization of HBM"

- 출처: arXiv 2203.15722 **v2** (2022-08-23, "Under review ... TMTT"). 출판판은 DOI 10.1109/TMTT.2022.3202221이다. 출판판과의 차이는 확인하지 않았다.
- 페이지는 arXiv PDF 기준이다.

| 항목 | 원문 (쪽) |
|---|---|
| 문제 | HBM VDDQ PDN (칩 + 인터포저). 375×375 μm² 단위 셀 격자이고, 전체 816 포트다. 그중 **probe 후보 48개**(PHY 영역)와 **decap 후보 768개**가 있다. 한 문제에서 probe는 **4개 무작위**, decap 후보는 **n개 무작위**다 (p.7, III-D). |
| decap | **한 종류**: 375×375 μm² NMOS unit decap, 1.055 nF, ESR 0.7 mΩ (p.4) |
| 놓는 개수 | **m개 고정** (문제 "n/m"). 12개 문제: 100/20·30·50·60, 200/20·40·60·100, 300/20·60·90·150 (p.10) |
| 목표 | **목표 임피던스·성공 여부가 없다.** 임피던스를 얼마나 줄였는지가 목표다. |
| 보상 | r = αr·Σ_P Σ_f (\|Z11_init\| − \|Z11_wDecap\|)/4 + (1−αr)·Σ_P Σ_f (\|Z21_init\| − \|Z21_wDecap\|)/6, αr = 0.7. f는 10 MHz~20 GHz 로그 간격 **166점** (p.4, 식 5) |
| 보상 시점 | **에피소드 끝에 한 번.** m개를 다 고른 뒤 Z 행렬을 cascade해 계산한다 (p.7, Fig. 6). 단계마다 Z를 다시 계산하지 않는다. |
| 상태 / 토큰 | 노드마다 (x, y, z 좌표, isProbingPort)인 **4차원**. 전기적 특징은 없다 (p.4, 식 3) |
| 정책 | attention encoder–decoder (AM 계열). 문맥 노드 = probe 4개 임베딩 + 전체 평균 (dhc = 6·dh). 이미 고른 노드는 마스킹한다. dx = 8, dh = 16, dv = 16 (p.6~9) |
| 학습 | REINFORCE + **rollout 기준선** (매 epoch 끝에 paired t-test로 갱신). Adam, lr 1e-4, epoch마다 ×0.95, epoch 20회, epoch 크기 1000, batch 100, val 100. 학습·val·test 문제 1000 / 100 / 100. **모방 학습은 없다** (p.7~9, Table III) |
| 디코딩 | greedy, 또는 sampling (폭 10~1000) |
| 평가 | test 100문제의 평균 보상 vs GA·RS (Table IV). 같은 성능에 도달하는 시간·비용 (Table V: 100/20에서 11 s vs GA 3 h 이상). 학습 시간 100/20 2200 s (Table VII) |
| 일반화 | probe 위치·후보 위치는 새 문제에서 재학습 없이 푼다. n과 m이 커져도 된다 (100/20으로 학습 → 큰 n, 20% → 50~60% 배치). **같은 HBM PDN 하나 안에서만** 시험했다. |

**우리 재구현(`bp_park_*`)과 비교할 때 적어야 할 차이**

1. 원 논문은 **개수 고정 + 임피던스 감소 최대화**이고, 우리는 **목표 만족 + 개수 최소화**다. 그래서 Park의 정책 구조와 입력을 우리 문제로 옮긴 것이지 원 논문 재현이 아니다. 보상과 멈춤 조건이 다르다.
2. 원 논문은 decap이 한 종류이고, 우리는 라이브러리 3종이다. 종류 선택 행동을 어떻게 붙였는지 적는다.
3. 원 논문의 입력은 좌표 + probe 여부뿐이다. 우리 재구현에 다른 특징이 들어갔으면 차이로 적는다.
4. 원 논문은 **RL만 쓰고, 기준선은 rollout + t-test 갱신**이다. 우리 `bp_park_rl`은 증류 → RL이고, `bp_park_rlonly`가 원 논문에 더 가깝다. 기준선 종류(그룹 평균인지 rollout인지)를 적는다.
5. 원 논문은 보상을 끝에서만 계산하고 Z를 단계마다 갱신하지 않는다. 우리 환경은 단계마다 정확 갱신을 한다. 정책 입력에 그 갱신이 들어가는지 적는다.
6. 학습 규모: 원 논문은 문제 2만 개(20 epoch × 1000)로 학습했다. 우리 예산(시간, 문제 수)과 나란히 적는다.

## 2. Manoharan, Wang, Hwang — TSIPI 2026 (박사논문 Paper I)

- 출처: H. Manoharan 박사논문 "Machine Learning Based Automation of PCB PDN Design and Optimization", Missouri S&T, 2026. Scholars' Mine doctoral_dissertations/3459, Paper I, pp. 6–44. 랜딩 페이지에 "submitted to IEEE TSIPI"라고 적혀 있다.
- 사람이 2026-10-19에 전문을 읽고 적은 메모를 옮겼다. 지금은 서버와 이 세션 모두에서 PDF를 받을 수 없다 (403). 출판판과의 차이는 확인하지 않았다.

| 항목 | 원문 (메모) |
|---|---|
| 문제 | 실제 PCB post-layout. **목표 임피던스를 만족**하면서 decap을 배치한다. 지표는 개수와 목표 만족 여부다. |
| 포트 순서 | **규칙으로 고정**: 포트마다 한 주파수 f0(중간 대역)에서 잰 loop inductance로 greedy 순위를 매긴다. 정책은 그 순서대로 **각 포트에 어떤 decap을 놓을지만** 고른다. |
| 포트 특징 | f0에서의 loop inductance 스칼라 + 패드 크기 one-hot. **좌표는 없다.** |
| 상태 | ΔZ = Z_IC − Z_target을 **n_f개 고정 주파수 점**에서 잰 벡터를 MLP로 임베딩한다. decap은 특징 벡터 토큰이다. |
| 갱신 | **매 단계 Schur 보수로 전체 Z 행렬을 정확 갱신**한다 (식 6). |
| 학습 | REINFORCE + **critic + replay buffer**. 랜덤 PCB 25~75 포트, Murata 라이브러리 약 1000종, **에피소드 5만 회**, **RTX 4090 약 24시간**. |
| 시험 | 처음 보는 PCB와 라이브러리, 10 / 50 / 150 포트. GA v3와 비슷하거나 더 적은 개수이고, 시간은 수백~수천 배 빠르다 (150 포트: GA 64분 vs 1.3초). |
| 다른 데이터셋 (4.2절) | DevFormer(probe 1, 포트 100)와 Park(probe 4, 포트 100) 데이터셋에서 **재학습 없이 목표를 만족**했다. 단, 사례 2개이고, 예산을 맞춘 비교이며, 목표가 0.5 Ω로 느슨하다. |
| **미확인** | 보상 식의 정확한 형태 (단계 보상인지 끝 보상인지, 개수·실패 벌점), "놓지 않음/건너뜀" 행동이 있는지, 에피소드 종료 조건, n_f 값과 주파수 범위, 네트워크 크기, batch와 lr. → **원문 PDF가 있어야 확정할 수 있다.** 그 전까지는 우리 재구현의 선택으로 적고 "원문 미확인"을 붙인다. |

**우리 재구현(`bm_manoharan_*`)과 비교할 때 적어야 할 차이**

1. **학습 예산이 가장 크게 다르다.** 원 논문은 RTX 4090에서 약 24시간, 에피소드 5만 회다. 우리는 RL만 2.0 h다. pcb 0.00은 예산 차이일 수 있다. 결론에는 "같은 예산 2 h에서"를 붙인다.
2. 원 논문은 **처음부터 RL**(critic + replay)이다. `bm_manoharan_rl`(증류 → RL)은 원 논문과 다르다. `bm_manoharan_rlonly_l20`이 더 가깝지만, critic + replay를 쓰지 않으면 그것도 차이로 적는다.
3. 포트 순서 규칙, f0 선택, n_f 주파수 점을 원문 메모와 대조해서 적는다.
4. 원 논문은 PCB에서만 학습했다. 우리 재구현은 세 종류 모두로 학습했다.
