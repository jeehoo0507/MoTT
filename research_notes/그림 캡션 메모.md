# 그림 캡션 메모 (에이전트 초안, 2026-11-05 라운드 48)

보고서 캡션에 넣어야 할 조건·주의만 모음. 숫자는 여기 적지 않는다 — 각 항목의 RESULTS 표에서 읽는다 (`scripts/collect_results.py` 자동 생성).

## 그림 1 — `reports/fig1_board_draft_r2pk_10.png`
- 방법: 채택 구조 `r2pk_rl` (2단 MoTT + P1 `--peak_refine`), seed 0, 세 종류를 섞어 학습한 모델 하나.
- 판: 10×10 `eval_{pcb,pkg,ip}10_0`, 문제 고르기 `fig_board.py --pick median` (정확 검사 성공 문제 중 개수 중앙값; 결과 보기 전 규칙, 옛 r3 초안과 같음).
- 곡선은 `verify.py`와 같은 `check_freqs()` 격자로 그림; 최악 |Z|/Zt 값은 그림 안 글자.

## 그림 2 — `reports/fig2_bigboard_draft_r2pk.png` (`fig_results.py --fig 2 --sizes 16,20`)
- 시간 = 문제당 **평균** 초 (판 준비 제외, 같은 CPU), seed 0. 16칸 pcb의 r2pk 평균은 `eval_pcb16_0` #9 한 문제 (199개 놓고 실패)가 끌어올림 — 고르지 않고 그대로 둠, 캡션에 "평균, 폭주 한 문제 포함".
- 속도 차는 "수백 배"가 아니라 RESULTS "규모 곡선" 표의 문제당 초 그대로 적는다.
- 개수비는 **둘 다 성공한 문제만** — 실패를 가리므로 성공률 행과 같이 읽는다.
- 20칸은 파일당 8문제 × 2 = 16문제 (QUEUE 10/29 (c)) → "작은 표본", CI는 규모 곡선 표.
- LS 열: 16칸 LS는 메모리 45 GiB 규칙 때문에 일부 파일이 "메모리로 생략" (`*.memskip`, RESULTS에 자동 표시). 다시 돈 파일은 `--ls_chunk 8` (메모리만 바꿈, 10칸에서 해가 비트 단위 같음 확인) — 시간은 묶음 크기가 달라 LS10과 조건이 다름 (기록의 `ls_chunk`).

## 그림 3 — `reports/fig3_ladder_seeds_draft_r2pk.png` (`fig_results.py --fig 3 --seeds`)
- 막대 = seed 0·1·2 평균, 점 = seed. 기준선 E0+ (종류 인식 greedy)·`modal_rule`은 가로선.
- `r2pk_rl`은 사다리 단이 아니다: 2단 + 입력 하나 (P1). 막대 이름 그대로 두고 캡션에 적는다.
- seed 0 기록은 day 1 평가 설정, seed 1·2는 `--inst_chunk 5` — 평가 배치 잡음 (같은 가중치에서 50문제 중 ~3문제가 바뀜) 있음.

## 정성 그림 — `reports/fig_rule_vs_mott_{ip16,pcb20}.png`
- 같은 판에서 `modal_rule` vs `r2pk_rl`. 판 고르기 (QUEUE 11/05 08:05 KST, 결과 전 고정): 둘 다 정확 검사 통과 중 개수 차 (modal_rule − r2pk_rl)가 파일 중앙값에 가장 가까운 문제, 동률이면 작은 인덱스.
